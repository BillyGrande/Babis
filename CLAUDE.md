# edge-deployer

## What This Is

An open-source toolkit for operating fleets of **autonomous ArgoCD edge
clusters** — including air-gapped ones — from one central pane of glass,
without ever requiring inbound connectivity to an edge.

Two deliverables, one module:

- **`edgedeploy`** (CLI, runs on each edge): installs/converges ArgoCD via
  Helm (online or from a local air-gap OCI registry), applies the ArgoCD
  Application manifests that drive the rest of the stack, and pushes compact
  status reports to the central operator. `report` is a one-shot designed
  for cron/systemd timers — deliberately **not** a resident agent.
- **operator** (runs in one central cluster): receives reports on an HTTP
  ingest endpoint and materializes them as `Edge` custom resources — the
  fleet inventory. A reconciler flips each Edge's `Reachable` condition when
  heartbeats stop. `kubectl get edges` is the fleet dashboard.

Positioning: complements — does not replace — [argocd-agent] and hub-spoke
ArgoCD. The niche is fleets of fully autonomous installs (each edge owns its
ArgoCD) and disconnected/air-gapped environments where day-0 happens from a
local artifact store (e.g. [Hauler]) and telemetry is outbound-only.

[argocd-agent]: https://github.com/argoproj-labs/argocd-agent
[Hauler]: https://hauler.dev

## Architecture

```
 EDGE (each site)                        CENTRAL CLUSTER
┌──────────────────────────┐            ┌─────────────────────────────┐
│ ArgoCD (autonomous)      │            │ edge-deployer operator      │
│  ▲ helm install          │  HTTPS     │  ├─ ingest :8090  ◄─────────┼── POST /api/v1alpha1/reports
│ edgedeploy CLI           │  outbound  │  └─ Edge reconciler         │
│  ├─ bootstrap / apply    │  only      │       (Reachable condition) │
│  └─ report (cron) ───────┼───────────►│ Edge CRs = fleet inventory  │
│ [optional] local OCI     │            │  `kubectl get edges`        │
│ registry for air-gap     │            └─────────────────────────────┘
└──────────────────────────┘
```

Reachability is inferred, never probed: no report within the heartbeat
timeout (default 15m, per-edge override via `spec.heartbeatTimeout`) flips
the condition to False. The operator never dials an edge.

## Layout

```
cmd/edgedeploy/          # CLI entry (signal-aware context)
cmd/operator/            # controller-runtime manager + ingest runnable
api/v1alpha1/            # Edge CRD types (group fleet.edgedeployer.io)
internal/cli/            # cobra wiring only — constructors, no globals
internal/argocd/         # helm install + Application state via kubectl
internal/manifests/      # collect/render/apply (.yaml + .yaml.tmpl Go templates)
internal/execx/          # exec wrapper with --dry-run / --verbose
internal/wire/           # report JSON contract between CLI and operator
internal/operator/
  controller/            # Edge reconciler (pure Reachability() core)
  ingest/                # HTTP ingest -> Edge status (auto-registration)
config/crd/, config/rbac/  # generated by controller-gen — never hand-edit
```

## Design Rules

- **Outbound-only edges.** Nothing in this project may require the central
  side to reach an edge. Any feature that needs it is out of scope.
- **CLI on edges, operator centrally.** Edges get a single static binary
  invoked by cron/systemd — no resident agent to upgrade or babysit. All
  long-lived reconciliation lives in the central operator.
- **CRDs are the state store.** Fleet state lives in Edge objects
  (status subresource), not a database. If history/analytics ever land,
  they'll be a separate consumer, not a replacement (see Roadmap).
- **Shell out on the edge, client-go in the center.** The CLI wraps
  whatever `kubectl`/`helm` are on PATH (overridable via `--kubectl`/
  `--helm`) — small binary, respects user kubeconfig, distribution-agnostic.
  The operator uses controller-runtime, as an operator should.
- **Strict rendering.** `.yaml.tmpl` Go templates run with
  `missingkey=error`; a typo can never silently produce an empty value.
- **The wire format is a contract.** `internal/wire` is consumed by both
  sides; once released, changes must be backward compatible (old CLIs keep
  reporting to new operators).
- **No package-level mutable state.** Commands/servers are built by
  constructors; contexts flow from `signal.NotifyContext` /
  `ctrl.SetupSignalHandler()` into every exec and HTTP call.
- **Tests are table-driven** and never need a cluster: pure logic
  (`Reachability`, rendering, wire validation) plus handler tests against
  controller-runtime's fake client.
- **Boring on purpose.** Dependencies: cobra, controller-runtime, and
  what they drag in. No frameworks. Small, single-purpose packages.

## Dev Workflow

```bash
make check        # fmt + vet + staticcheck + test — run before every commit
make build        # builds bin/edgedeploy and bin/operator
make generate     # controller-gen: deepcopy after editing api/
make manifests    # controller-gen: config/crd + config/rbac after editing api/ or RBAC markers
```

After ANY change under `api/`, run `make generate manifests` and commit the
generated files. CI fails if they drift.

Local end-to-end: `kind create cluster`, `kubectl apply -f config/crd/`,
`go run ./cmd/operator --fleet-namespace default`, then from any machine
with a kubeconfig+ArgoCD: `edgedeploy report --hub http://localhost:8090`.

## Versioning / Compatibility Notes

- API group `fleet.edgedeployer.io`, version `v1alpha1` — breaking CRD
  changes are fine until v1beta1, but bump the version when they happen.
- CLI version is stamped via
  `-ldflags "-X github.com/BillyGrande/edge-deployer/internal/cli.Version=..."`
  (see Makefile `release`).
- Ingest auth is a shared bearer token (`EDGEDEPLOY_INGEST_TOKEN` on the
  operator, `EDGEDEPLOY_TOKEN` on edges). Known v1 limitation.

## Roadmap

1. **v0.1**: what's here — bootstrap/apply/status/report + Edge inventory
   with reachability. Harden, docs, kind-based e2e, release binaries.
2. **Air-gap first-class**: `edgedeploy airgap` subcommands wrapping a local
   Hauler store/registry (load, serve, health), store version detection so
   `report --store-version` stops being a manual flag.
3. **Operator deploy assets**: Helm chart or kustomize under `config/`,
   container image, TLS/ingress guidance for the ingest endpoint.
4. **Per-edge auth**: token-per-edge or mTLS; auto-provisioning flow.
5. **History/analytics**: optional consumer persisting reports (Postgres)
   for "when did this edge last drift" questions — additive, CRDs stay the
   source of truth for current state.
6. **argocd-agent interop**: report enrichment for hybrid fleets (some
   edges autonomous, some agent-managed).
