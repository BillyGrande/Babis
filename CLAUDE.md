# Babis

## What This Is

Toolkit for operating fleets of **autonomous ArgoCD edge clusters** (air-gapped
included) from one central pane of glass, with no inbound connectivity to edges.
Two deliverables, one module: the **`babis` CLI** on each edge (installs ArgoCD
via Helm, applies Applications, pushes `report` one-shots from cron/systemd) and
a central **operator** (HTTP ingest -> `Edge` CRs, `Reachable` condition).
Complements — does not replace — [argocd-agent]. Read `docs/positioning.md`
(hard non-goals, litmus tests) before adding features; design and diagram in
`docs/architecture.md`.

[argocd-agent]: https://github.com/argoproj-labs/argocd-agent

## Layout

- `cmd/babis/`, `cmd/operator/` — entry points (CLI; controller-runtime manager + ingest)
- `api/v1alpha1/` — Edge CRD types (group `fleet.babis.dev`)
- `internal/cli/` — cobra wiring only; constructors, no globals
- `internal/argocd/` — helm install + Application state via kubectl
- `internal/manifests/` — collect/render/apply (`.yaml`, `.yaml.tmpl`)
- `internal/execx/` — exec wrapper with `--dry-run` / `--verbose`
- `internal/wire/` — report JSON contract between CLI and operator
- `internal/operator/controller/`, `ingest/` — Edge reconciler (pure `Reachability()`); HTTP ingest
- `config/crd/`, `config/rbac/` — generated by controller-gen, **never hand-edit**
- `docs/` — architecture, positioning, roadmap

## Design Rules

- **ArgoCD-only, by design.** No abstraction over other GitOps engines (no Flux support, no generic layer). Prefer ArgoCD's own integration points — Application status, the cluster secret, notifications, the upstream install manifests/chart — over new Babis mechanisms.
- **Outbound-only edges.** Nothing may require central to reach an edge.
- **CLI on edges, operator centrally.** Single static binary via cron/systemd, no resident agent. Long-lived reconciliation lives in the operator.
- **CRDs are the state store.** Fleet state is Edge status, not a database; history would be a separate consumer.
- **Shell out on the edge, client-go in the center.** CLI wraps `kubectl`/`helm` on PATH (`--kubectl`/`--helm`); operator uses controller-runtime.
- **Strict rendering.** `.yaml.tmpl` runs with `missingkey=error`.
- **Wire format is a contract.** Released changes must be backward compatible (old CLIs keep reporting to new operators).
- **No package-level mutable state.** Build commands/servers via constructors; pass contexts from `signal.NotifyContext` / `ctrl.SetupSignalHandler()` into every exec and HTTP call.
- **Tests are table-driven** and need no cluster: pure logic plus handler tests on controller-runtime's fake client.
- **Boring on purpose.** Deps: cobra, controller-runtime, and what they drag in. No frameworks; small single-purpose packages.

## Dev Workflow

```bash
make check        # fmt + vet + staticcheck + test
make build        # bin/babis and bin/babis-operator
make generate     # deepcopy after editing api/
make manifests    # config/crd + config/rbac after editing api/ or RBAC markers
```

Local e2e: `kind create cluster`, `kubectl apply -f config/crd/`,
`go run ./cmd/operator --fleet-namespace default`, then on a machine with
kubeconfig+ArgoCD: `babis report --hub http://localhost:8090`.

## Verification (before reporting done)

- Run `make check`. It must pass.
- If anything under `api/` or an RBAC marker changed: run `make generate manifests` and include the generated files in the same commit. CI fails on drift.
- If `internal/wire` changed: confirm it is backward compatible (old CLIs still accepted by new operators); add or update a table-driven test in `internal/wire`.
- New logic gets a table-driven test that needs no cluster.

## Change workflow

This repo follows the [AI-native SDLC playbook]: each stage commits an
artifact that the next stage reads, and a human reviews at each gate. The
rules below are the binding part. The playbook is background.

[AI-native SDLC playbook]: https://claude.com/resources/articles/the-ai-native-sdlc-playbook

Every feature starts in `changes/NNNN-<slug>/`:
`intent.md` (problem, outcome, users, constraints, open questions) ->
`spec.md` (requirements + design, includes the `docs/positioning.md` litmus-test check) ->
`plan.md` (from plan mode: files, order, risks, proof).
Do not implement before `plan.md` is accepted. If implementation drifts, update
`plan.md` in the same commit. Items in `docs/roadmap.md` are the backlog.

## Versioning / Compatibility

- API `fleet.babis.dev/v1alpha1`; breaking CRD changes are fine until v1beta1, but bump the version when they happen.
- CLI version via `-ldflags "-X github.com/BillyGrande/babis/internal/cli.Version=..."` (Makefile `release`).
- Ingest auth is a shared bearer token (`BABIS_INGEST_TOKEN` operator, `BABIS_TOKEN` edges). Known v1 limitation.
